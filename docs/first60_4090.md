## 环境与调试修改

环境：`/kiri/envs/genrecon`；Python 3.12.3、Torch 2.10.0+cu128、CUDA toolkit 12.8、
RTX 4090 24GB。实际容器 RAM 上限约 57.7 GiB。
详细版本、依赖源码提交、权重来源/hash、CUDA 小核检查见 `protocol/`。

为跑通并控制显存，fork 中增加/修复了：

1. 发布权重缺失原训练目录配置时，按明确的发布权重名称使用仓库训练配置；记录
   checkpoint 加载报告。三套权重无缺失、额外或形状不匹配的键。
2. DINO 每次编码 2 个裁切，特征缓存到 CPU；投影聚合避免构造完整三路拼接大张量。
3. SS 噪声按照 flow 模型的 16³ latent 分辨率生成，再解码为 32³ occupancy。
4. 将已有的空间分组解码用于 512，首测每组 1 块，目标 20,000 个 inflated voxels。
   该数量是分组目标，不能拆分单个块，本次最大组仍有 20,542 个。
5. 修复 IphoneChunker 的 `skip_point_cleaning` 参数；增加输入计数、显存/时间记录、
   GPU 锁及运行源码快照。
6. GLB 导出异常使用非零退出码，避免把失败记录成成功。
7. 修复上游分组解码的重叠区域归属：完整 chunk AABB 实际有交叠，不能分别作为
   互斥的输出区域。现在只在覆盖当前格点的 chunks 中选择最近中心作为唯一 owner，
   平局按输入顺序确定。面用固定 lattice 顶点中心的重心、纹理用 voxel 中心，
   两者共享规则，避免预测顶点的小幅变化改变面归属。保留解码所需 inflated 上下文。

第 7 项修复前，`attempt_02` 纹理坐标额外重复 5,706,583 条，固定 chunk005 区域
额外重复 121,370 面（74.04%）。修复后全场精确重复面和纹理坐标均为 0，
证据在 `protocol/attempt03_ownership_duplicate_evidence_summary.json`。
该统计不代表所有几何/拓扑都正确。

FlashAttention 为本机 **推理专用** 2.8.3.post2+infer89 构建，保留标准 head 维度的
FP16/BF16 前向，关闭反向、dropout、ALiBi、local window 和 softcap。本次调用只用
默认全局注意力。以后训练或需要这些功能时需完整重建。补丁和重建记录在
`scripts/dependency_patches/` 与运行根目录 `protocol/environment/`。

18 项 CPU 回归检查、15 项非 Flash 环境检查、Flash dense/varlen 实际 CUDA 对照
检查及 CuMesh 的 15 项零工作量/正常拓扑 CUDA 检查通过。

## 重跑

已有数据和权重不必重复准备；每次指定一个新的 attempt 名称，避免覆盖已有记录：

```bash
cd /kiri/GenRecon
GENRECON_ATTEMPT=attempt_04 bash scripts/run_first60.sh
```

脚本默认使用这次的本机环境/权重/数据路径，可通过 `GENRECON_PYTHON`、
`GENRECON_RUN_ROOT`、`GENRECON_WEIGHTS` 覆盖。详细命令在每个 attempt 的 `run.json`。

重新准备独立子集时需空目录：

```bash
/kiri/envs/genrecon/bin/python scripts/prepare_ffba_subset.py \
  --source /kiri/529_prior_pose_and_k_moge3_20261021 \
  --output /path/to/new/run/data --count 60
```

大网格的完整几何检查与 FFBA 导出：

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=4 /usr/bin/python \
  scripts/inspect_ffba_large_result.py \
  --result-dir /path/to/attempt/result \
  --data-dir /path/to/run/data \
  --source-dataset /kiri/529_prior_pose_and_k_moge3_20261021 \
  --output /path/to/new/inspection --threads 4
```

本次 CPU 检查 17.76 秒、RSS 峰值 2.75 GiB。没有运行全局连通分量分析，
报告明确标记未检查该项；也未依此过滤网格。
